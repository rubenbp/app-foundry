# Validación de recuperación operativa por comentarios

Fecha: 18 de octubre de 2026.

La Factory notifica las incidencias y procesa las órdenes completas `Reintentar`, `Corregir: instrucciones` y `Cancelar` mediante comentarios humanos del issue, sin comprobar permisos del autor. La aceptación del resultado y el merge conservan sus reglas.

| Comportamiento                                                                                                                                                           | Evidencia automatizada                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Avisar una vez de cada incidencia y consumir una orden una sola vez, excluyendo bots.                                                                                    | [Flujos de recuperación](../../../tests/issueRecovery.test.ts).                                                                                 |
| Reintentar preparación sobre el mismo clon y verificar antes de entregar el encargo al agente.                                                                           | [Prueba de instalación fallida](../../../tests/issueRecovery.test.ts).                                                                          |
| Reintentar verificación completa sin otro Intento del agente.                                                                                                            | [Prueba de verificación fallida](../../../tests/issueRecovery.test.ts).                                                                         |
| Reintentar un fallo del agente en otro Intento del mismo thread.                                                                                                         | [Prueba de reintento de implementación](../../../tests/issueRecovery.test.ts).                                                                  |
| Corregir un candidato aceptado conservando conversación, rama y PR; publicar otro commit y exigir verificación y aceptación nuevas hasta completar el merge y el cierre. | [Recorrido de corrección](../../../tests/issueRecovery.test.ts).                                                                                |
| Actualizar la rama publicada usando el SHA anterior y rechazar una concesión obsoleta.                                                                                   | [Adaptador de publicación con Git real y remoto local](../../../tests/githubPublication.test.ts).                                               |
| Cancelar sin permisos, confirmar parada y cerrar como no implementado; mantener issue abierto y reserva si la parada no se confirma.                                     | [Flujos de cancelación](../../../tests/issueRecovery.test.ts) y [contrato `not_planned` de GitHub](../../../tests/githubInterventions.test.ts). |
| Impedir corregir o cancelar después del merge; permitir completar el resumen y el cierre con `Reintentar`.                                                               | [Límite posterior al merge](../../../tests/issueRecovery.test.ts).                                                                              |
| Distinguir órdenes explícitas de consultas y conservar instrucciones literales.                                                                                          | [Gramática de recuperación](../../../tests/recovery.test.ts).                                                                                   |

Las pruebas del workflow usan persistencia, artefactos, clon y commits Git reales con fronteras remotas controladas. La prueba de publicación usa un repositorio Git bare local; el contrato del cierre verifica la petición `state_reason: not_planned`. No se ha publicado una corrección ni cancelado un issue real en GitHub durante esta validación.

El alcance es el flujo natural del MVP. No incorpora una cola de avisos ni nuevos mecanismos para recuperar comunicaciones con GitHub. Las evidencias anteriores de aclaraciones, verificación e integración conservan su alcance histórico.
